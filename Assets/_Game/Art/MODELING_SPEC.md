# 모델링 규격서 — 해상 로그라이크 프로토타입

이 문서는 **이 프로젝트에 들어갈 3D 에셋을 만드는 사람/에이전트가 지켜야 할 규칙**이다.
여기 적힌 이름과 축 방향은 게임 코드가 직접 찾아 쓰기 때문에, 임의로 바꾸면 기능이 조용히 멈춘다.

---

## 0. 한눈에 보는 체크리스트

납품 전 아래를 모두 확인한다.

- [ ] 단위 **미터**, Blender 씬 스케일 1.0
- [ ] **스케일·회전 적용** (Ctrl+A → Apply All Transforms). 오브젝트 스케일이 1.0, 회전이 0
- [ ] 내보낸 FBX의 루트에 **100배 스케일이 남아있지 않은가** (§7 Apply Scalings 참고)
- [ ] 선수(뱃머리)가 **Blender +Y** 를 향함 → Unity에서 +Z가 된다
- [ ] 원점(오리진)이 규격대로인가 (§2)
- [ ] **콜라이더용 메시를 넣지 않는다** — 코드가 BoxCollider를 붙인다
- [ ] 회전부·발사구가 **정해진 이름의 빈 오브젝트/부모**로 분리되어 있는가 (§4)
- [ ] 머티리얼 이름이 §5 목록과 일치하는가
- [ ] 카메라·라이트·아마추어를 내보내지 않았는가
- [ ] `.fbx` 로 내보냈는가 (`.glb`는 참고용, Unity는 FBX를 읽는다)
- [ ] 폴리곤 예산(§6)을 넘지 않는가
- [ ] **면 방향(노멀)이 바깥을 향하는가** — Blender 뷰포트 Overlays → Face Orientation에서 **파란색**이어야 한다(빨강 = 뒤집힘).
      Blender는 뒷면도 그려서 멀쩡해 보이지만 Unity에서는 그 면이 **투명하게 뚫린다.** 고치기: 편집 모드 → 전체 선택 → Shift+N

## 1. 좌표계와 축

| 항목 | Blender | Unity(결과) |
|---|---|---|
| 위 | +Z | +Y |
| 선수(앞) | **+Y** | **+Z** |
| 우현(오른쪽) | +X | +X |

Blender의 glTF/FBX 익스포터는 **Blender +Y를 -Z로** 내보낸다.
따라서 **선수를 Blender +Y로 만들면** Unity에서 +Z(정면)가 되도록 임포트 측에서 맞춰져 있다.

> **확인 방법**: 내보낸 `.glb`를 열었을 때 뱃머리가 -Z에 있으면 정상이다.
> 모든 아트 모델(모듈·적·헬기)이 이 상태이고, 현재 프리팹 빌더는 별도 Y축 방향 보정 없이 사용한다.
> 새로 만들 때도 **같은 규칙을 유지**하면 된다. 다르게 만들면 알려줄 것.

## 2. 원점(오리진) 규칙

원점이 틀리면 모듈이 격자에서 어긋나거나 배가 물에 잠긴다.

| 에셋 종류 | 원점 위치 |
|---|---|
| **함선 모듈** | 발자국(footprint)의 **중심**, **바닥면이 y=0** (위로 자란다) |
| **적 함정** | 함 **중앙**, **흘수선이 y=0** (수면에 닿는 높이) |
| **잠수함** | 함 **중앙**, 부상 시 갑판이 보이도록 **선체 중심이 y=0** |
| **발사체·이펙트** | 기하 중심, 진행 방향은 +Z |

> **모듈은 갑판 위에 얹히는 것이 아니라 그 자체가 함체의 한 조각이다.**
> 함선에는 고정된 선체가 없다. 플레이어가 붙인 모듈을 따라 갑판판과 뱃전이
> 코드로 만들어지고, 모듈은 그 위에 선다. 그래서 모듈 아래쪽은 보이지 않으므로
> 바닥을 따로 만들 필요가 없다.

## 3. 크기 기준 (중요)

**한 칸 = 2m.** 함선은 고정 크기가 아니다. 함교(원점)에서 시작해 모듈을 맞붙여 자라며,
선수-선미로 최대 ±10칸, 좌현-우현으로 최대 ±3칸까지 뻗을 수 있다.
즉 최대 크기는 약 **42m × 14m**이고, 시작 함선은 **12m × 2m** 정도다(6칸).

적 함정은 이 범위를 기준으로 만든다.

### 3-1. 함선 모듈

한 칸은 **2m**. 칸 사이 간격이 보이도록 **실제 크기는 칸 크기의 90% 정도**로 만든다.

**함교만 3×1(앞뒤 3칸)이고 나머지 모듈은 모두 1×1 (1.8 × 1.8 m) 이다.**
함교 블록은 **함교 + 기관실 + 연돌**을 한 덩어리로 만든다. 별도의 기관 모듈은 없다.

| 모듈 | 격자 | 목표 크기 (X × Z) | 높이 기준 |
|---|---|---|---|
| **함교 (+기관실·연돌)** | **3×1** (앞뒤 3칸) | **1.8 × 5.8 m** | 함교탑 2.2~2.8 m, 연돌 2.6~3.0 m |
| 기관포 | 1×1 | 1.8 × 1.8 m | 1.2 m (포신은 칸 밖으로 나가도 됨) |
| CIWS | 1×1 | 1.8 × 1.8 m | 약 1.8 m (레이더 돔 포함, 포신은 칸 밖으로 나가도 됨) |
| 레이더 | 1×1 | 1.8 × 1.8 m | 2.5 m (마스트) |
| VLS | 1×1 | 1.8 × 1.8 m | 0.8 m (낮게) |
| 기만체 · 탄약고 · 손상통제반 · 소나 | 1×1 | 1.8 × 1.8 m | 0.6~1.0 m |
| 헬기데크 | 1×1 | 1.8 × 1.8 m | 0.3 m (패드) + 헬기 |
| 유도로켓 발사기 | 1×1 | 1.8 × 1.8 m | 1.6 m (발사관 포함) |
| **76mm 함포** | 1×1 | 1.8 × 1.8 m | 1.3 m (포탑 돔). 포신은 칸 밖으로 1 m 이상 나가도 됨 |
| **함대공 미사일 발사기** | 1×1 | 1.8 × 1.8 m | 1.4 m (**선회식 4연장 박스 발사기**, Sea Sparrow Mk29형. VLS의 평평한 셀과 헷갈리지 않게) — 흰 발사관 묶음, 청색 관 덮개, 약 40° 들림 |
| **전자전 장비** | 1×1 | 1.8 × 1.8 m | 1.4 m (장비함 + 짧은 마스트 + 안테나·레이돔) |
| 대잠 폭뢰 발사기 | 1×1 | 1.8 × 1.8 m | 0.9 m 이하 (**낮음** 등급 — 이웃 무기를 가리지 않게 낮게) |

크기가 같으므로 **실루엣과 색으로만 구별된다.** 위에서 비스듬히 봤을 때
무엇인지 한눈에 알아볼 수 있어야 한다.

**삭제된 모듈**: 장갑(손상통제반에 통합), 발전기(전력 시스템 폐지).

> 격자 표기 `W×H` 에서 **W는 선수-선미 방향(Unity Z)**, **H는 좌현-우현 방향(Unity X)** 이다.
> 높이는 자유지만, 갑판 장비는 **3m 이하**를 권장한다(카메라에 가린다).
> 포신·안테나가 칸 밖으로 삐져나오는 것은 괜찮다.

### 3-1-1. 함교 블록 (3×1) 상세

```
   선미(−Y)                                       선수(+Y)
   ┌──────────────┬──────────────┬──────────────┐
   │   연돌        │  기관실 상부  │   함교탑      │   ← 폭 1.8 m
   │ (Funnel)     │ (EngineHouse)│  + 마스트     │
   └──────────────┴──────────────┴──────────────┘
          2 m            2 m            2 m          합계 약 5.8 m
                         ▲ 원점(가운데 칸 중심, 바닥 Z=0)
```

- **원점은 가운데 칸의 중심**이다. 코드가 3칸 발자국의 중심에 맞춰 놓는다.
- 선수는 다른 모델과 같이 **Blender +Y**. 함교탑이 +Y 쪽, 연돌이 −Y 쪽.
- 파일명은 기존과 같은 **`MOD_Bridge.fbx`**. 들어오면 셋업 때 자동 교체된다.
  - 길이가 약 4m보다 짧은 예전 1칸 모델이면, 코드가 선수 칸에 올리고 나머지를 그레이박스로 채운다.
- 높이 등급은 **높음**(이웃 무기의 사격각을 가림). 연돌이 가장 높아도 된다.
- 폴리곤 예산: 1×1 모듈의 약 2.5배(최대 약 2,000 tris).

### 3-1-2. 함수(뱃머리) — 코드가 자동 생성, 소품만 모델링

**함수 형상 자체는 만들지 않는다.** 블록 배치가 매번 달라 고정 모델로는 맞출 수 없으므로
`ShipHullBuilder`가 배 앞 윤곽을 따라 메시를 생성한다.

```
   위에서 본 모습 (선수 ↑)

         ▲              ▲  끝점: 맨 앞 구간 중앙에서 2.4 m(1.2칸) 앞
        ╱ ╲            ╱█╲
       ╱   ╲          ╱ █ ╲    ← 계단은 경사면으로 메워 하나의 뱃머리가 된다
      █ █ █ █        █  ▀  █
```

생성 규칙(수치는 `ShipHullBuilder` 인스펙터에서 조정):

| 항목 | 값 |
|---|---|
| 끝점 길이 | 맨 앞 블록 앞면에서 **2.4 m** (1.2칸) |
| 함수 갑판 높이 | 갑판판 윗면과 같음 (격자 갑판 높이 + 약 0.1 m) |
| 뱃전 깊이 | 갑판 윗면에서 **1.6 m** 아래까지 — 선체 흔들림이 있어도 바다 평면 밑에 남아 밑이 비어 보이지 않음 (옆 뱃전 조각도 같은 깊이) |
| 플레어 | 아래로 갈수록 좌우 **20%** 모임 |
| 선수재 기울기 | 아래 끝이 앞으로 뻗은 길이의 **30%**만큼 뒤로 물러남 |
| 닻 | 좌우 뱃전, 맨 앞 블록 앞면에서 끝점 방향 **35%** 지점, 갑판 모서리 **0.35 m** 아래 |
| 재질 | 갑판 `MAT_hull_deck`, 옆면 `MAT_hull_side` |
| 판정 | **없음.** 격자 칸·체력·충돌 없음, 사격각을 가리지 않음 |

#### 닻 `HULL_Anchor.fbx` (선택 — 없으면 그레이박스)

좌우 뱃전 옆면에 하나씩 자동으로 붙는다. 사진 참고: 둥근 닻줄 구멍 테 + 거기 걸린 닻(자루·갈고리).

| 방향 | **Blender +Y = 선체 바깥쪽**(뱃전에서 밖을 보는 면). 좌우 공용 하나 — 코드가 방향을 돌린다 |

#### 함수 갑판 소품 `HULL_BowFittings.fbx` (선택)

넣으면 함수 갑판에 자동으로 올라간다: **뒤끝을 맨 앞 블록 앞면에 붙이고, 함수 폭에 맞춰 자동으로 줄인다**(시작 배처럼 앞 1칸이면 약 70%, 35% 미만이 되면 생략). 없으면 생략된다.
사진 참고: 닻 양묘기(원통 2개), 닻줄, 계류주(볼라드), 닻줄 구멍 덮개.

| 항목 | 규격 |
|---|---|

| 크기 | **폭 1.4 m × 길이 1.6 m 이내**, 높이 **0.5 m 이하** (함수가 좁은 배에서도 삐져나오지 않게) |
| 원점 | **바닥 중앙**, Z=0이 갑판 윗면 |

| 재질 | `Deck Grey`(갑판 장비), `Gunmetal`(닻줄), `Warning Yellow`(계류주 띠) 팔레트 사용 |
| 폴리곤 | 600 tris 이하 |
| 계층 | 루트 하나 아래 메시들. 회전·스케일 적용(1.0) |
| 판정 | 없음. 소켓 이름 불필요 |

### 3-1-3. 미사일·로켓 모델 (선택 — 없으면 그레이박스)

코드가 꼬리에 **불꽃 + 추진 연기(꼬리선·연기 뭉치)**를 자동으로 붙인다. 모델은 동체만 만들면 된다.

| 파일명 | 용도 | 길이 × 지름 | 색 |
|---|---|---|---|
| `MIS_PlayerRocket.fbx` | 유도로켓(130mm) | 1.0 × 0.16 m | 흰 동체, 붉은 탄두 |
| `MIS_PlayerVls.fbx` | VLS 대함미사일 | 2.1 × 0.36 m | **짙은 회색** 동체, 어두운 탄두, **노란 띠**, 큰 꼬리 날개 |
| `MIS_PlayerSam.fbx` | 함대공 요격미사일 | 1.3 × 0.15 m | **순백** 가는 동체, **청색 탄두**, 몸통 가운데 긴 날개 + 작은 꼬리 날개 |
| `MIS_EnemyAsm.fbx` | 적 대함미사일 | 1.6 × 0.28 m | **붉은 동체**(적 표시) |

- 원점 **동체 중앙**, **Blender +Y = 비행 방향(탄두)**.
- 꼬리 끝에 빈 오브젝트 **`Exhaust`** — 불꽃·연기가 나오는 곳. 없으면 동체 길이의 절반 뒤로 잡는다.
- 날개 4장(십자), 탄두·동체 경계 띠. 폴리곤 300 tris 이하.

## 4. 코드가 찾는 이름 (반드시 지킬 것)

코드는 아래 이름을 **정확히 일치**로 찾는다. 대소문자·언더스코어까지 동일해야 한다.
없으면 해당 기능이 동작하지 않고 콘솔에 경고가 뜬다.

### 4-1. 함선 모듈

| 모듈 | 필요한 오브젝트 | 역할 |
|---|---|---|

|---|---|

```
Assets/_Game/Art/Models/<이름>.fbx
Assets/_Game/Art/Models/Materials/<머티리얼 이름>.mat
```

### 파일 이름
| 종류 | 규칙 | 예 |
|---|---|---|
| 함선 모듈 | `MOD_<이름>` | `MOD_Ciws.fbx` |
| 적 | `Enemy<이름>` | `EnemySubmarine.fbx` |
| 발사체 | `PRJ_<이름>` / `MIS_<이름>` | `MIS_EnemyAsm.fbx` |

### Blender FBX 내보내기 설정
```
Path Mode        : Copy
Limit to         : Selected Objects (해당 모델만)
Object Types     : Mesh, Empty        ← 카메라·라이트·아마추어 제외
Transform
  Scale          : 1.0
  Apply Scalings : **All Local**   ← FBX All 로 하면 루트에 100배 스케일이 남는다
  Forward        : -Z Forward
  Up             : Y Up
  Apply Unit     : 켜기
Geometry
  Apply Modifiers: 켜기
  Smoothing      : Face 또는 Normals Only
```

> 참고용으로 `.glb`도 함께 내보내면 검수가 쉽다. 게임은 `.fbx`만 사용한다.

## 9. 새 모델이 게임에 반영되는 방법

1. 위 규격대로 `Assets/_Game/Art/Models/` 에 `.fbx` 를 넣는다
2. Unity 에디터에서 **`Naval > Setup Prototype Scene`** 실행
3. 셋업 스크립트가 임포트 설정을 고정하고, 프리팹의 `Model` 자식을 교체하며,
   §4의 이름을 찾아 기능(조준·발사·회전)을 자동으로 연결한다
4. 모듈은 **정비 카드용 아이콘이 자동으로 구워진다** (`Art/Icons/ICON_<id>.png`).
   카드 가운데에 이 그림이 들어가므로, 위에서 비스듬히 봤을 때 무엇인지
   알아볼 수 있는 실루엣이어야 한다

**모델이 없으면 자동으로 그레이박스(Cube/Cylinder)로 되돌아간다.** 게임은 항상 실행된다.

손으로 프리팹을 새로 만들 필요는 없다. 오히려 만들면 로직 배선이 끊어진다.

## 10. 자주 나는 실수

| 증상 | 원인 |
|---|---|
| 모델이 옆으로 누움 | 회전을 Apply 하지 않았거나 Up 축이 Z |
| 모델이 100배 | **Apply Scalings가 "FBX All"** — 루트 노드에 `Lcl Scaling 100`이 남는다. "All Local"로 내보낼 것 |
| 모델이 0.01배 | Apply Unit 꺼짐 |
| 배가 뒤로 감 | 선수를 Blender -Y로 만듦 |
| 포신이 반대로 겨눔 | `Muzzle`이 `TurretPivot`의 -Z쪽에 있음 (코드가 자동 보정하지만 +Z 권장) |
| URP에서 분홍색 | 머티리얼이 Built-in Standard 셰이더 |
| 모듈이 칸을 벗어남 | 원점이 발자국 중심이 아님 |
| 적이 물에 잠기거나 떠 있음 | 원점이 흘수선이 아님 |
