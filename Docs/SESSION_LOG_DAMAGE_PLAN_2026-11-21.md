## 2. 기획 A — 「손상 통제」: 맞은 자리마다 망가지는 해전 (**미착수**)

사용자 요청: "너의 능력을 보여줄 만한 업데이트를 계획해 줘(실행은 하지 말고)". 사용자 평가: "계획은 좋다".

### 핵심 규칙
1. **구획 침수와 부력**
   - 블록 격자를 격벽 기준 4~6구획으로 나눈다.
   - 수면선 아래 구멍 → 물이 들어오고 약한 격벽을 넘어 번진다.
   - 물의 무게와 위치로 실제 기울기 · 흘수를 계산한다.
   - 기울면 속도 · 명중 저하, 한쪽 현 포는 사격 불가.
   - 시작값: 구획 하나가 다 차면 속도 −12%, 기울기 1°당 명중 −3%, 15° 넘으면 전복 경고.
2. **화재와 탄약고**
   - 갑판 피격 → 불이 붙어 블록을 따라 번진다.
   - 탄약고 · 발사관에 닿으면 유폭 카운트다운.
   - 연기는 레이더 · 시야를 일부 가리고, 적에게 위치를 드러낸다.
3. **손상 통제반**
   - 2개 조. 기본은 자동(화재 → 탄약고 → 침수 순).
   - 키 하나로 함선 도해를 열어 직접 배치할 수 있다.
   - 반대쪽 구획에 일부러 물을 채우는 역침수로 기울기를 바로잡는다(속도를 잃고 사격각을 얻음).

### 적 · 로그라이크 연결
- 무기별로 맞히는 곳이 다르다: 어뢰 · 기뢰는 수면선 아래(침수), 폭탄 · 로켓은 갑판(화재), 대함 미사일은 중간.
- 정예 · 보스는 기운 쪽 · 불난 배를 노린다.
- 업그레이드 후보: 강화 격벽 · 대용량 펌프 · 자동 소화 · 탄약고 차폐 · 손상 통제반 +1.
- 함급 차이: 강습함은 구획이 적어 금방 위태, 구축함은 오래 버팀.
- 적 함정은 구획 개념만 가볍게 적용해 격침 연출에 쓴다(함미부터 잠김 · 불타며 표류).

### 기술 · 검증
- 고정 간격 시뮬레이션이라 배속을 바꿔도 결과가 같다.
- 원래 재질은 그대로 두고 덧그림으로 표현한다.
- 화면 없이 수백 판을 돌리는 밸런스 시뮬레이터로 생존율 · 격침 원인을 표로 뽑는다.
  - 목표: 손상 통제를 잘하면 생존율 +15%p, 방치하면 지금보다 −10%p.
- 자동 검사: 기울기 부호 · 역침수 복원 · 유폭 · 배속 일치 · 저장 복원 · 성능.

### 진행 순서
구획 · 침수 → 화재 · 탄약고 · 무기별 맞히는 곳 → 손상 통제반(자동 → 수동) → 업그레이드 · 적 AI · 격침 연출.
단계마다 설정으로 켜고 끌 수 있게 한다. WWII는 현대에서 검증한 뒤 붙이는 것을 권장.

## 3. 문제 B — 적 미사일 · 자폭 드론이 함교만 공격함 (**미착수**)

### 원인 (코드 확인)
- 미사일: 기함 기준점 + 높이 0.8m를 겨눔 — `Scripts/Combat/Missile.cs` `AimPoint()`.
- 자폭 드론: 기함 기준점으로 급강하 — `Scripts/Enemies/KamikazeDrone.cs` `UpdateBehaviour`.
- 맞은 블록 = 맞은 지점에서 가장 가까운 칸 — `Scripts/Ship/DamageResolver.cs` `HitCell`. 위에서 가운데로 꽂히니 늘 가운데 칸.
- 시작 함정 4종 모두 함교가 `(-1, 0)`, 즉 한가운데.
- 함교는 기만체 · 응급 수리 · 레이더 · 전속을 혼자 맡고, 부서지면 재장전 ×1.35 · 사거리 ×0.85 · 선회 ×0.7. 가장 중요한 블록이 거의 모든 미사일을 맞는다.

### 조정안
1. **공격 종류별 맞는 자리**
   - 수면을 스치는 대함 미사일 = 다가오는 쪽 옆면 칸.
   - 급강하 미사일 · 자폭 드론 = 갑판 전체에서 칸마다 같은 확률.
2. **일제 사격 분산**: 같은 일제 사격의 미사일이 같은 칸을 고르지 않게 한다(`TargetAllocator`를 칸 단위로 확장).
3. **조종으로 대응**: 미사일 쪽으로 함수를 돌리면 앞쪽 블록 몇 개만 맞는다.
4. **함교 저격은 의도된 패턴으로만**(선택): 일부 정예만 레이더 전파를 쫓는 미사일로 함교 · 레이더를 노리고, 발사 때 노리는 블록에 표식을 띄운다 → 기만체 · 회피로 대응.

### 구현 · 검증
- 발사 순간 칸 하나를 골라 기억하고, 그 칸의 현재 위치로 유도한다.
  - 보스용 `IAimPointProvider` 방식을 기함에도 붙인다.
  - 원본 데이터 수치는 건드리지 않는다.
- 목표:
  - 함교 피격 비율 ≈ 함교 칸 비율 ±5%p
  - 옆면 공격은 다가온 쪽 칸에만
  - 한 일제 사격에서 같은 칸 중복 0
- 판 단위 생존율 · 격침 원인을 전후로 비교한다.

### 사용자 결정 대기
- 4번(함교 저격 미사일)을 넣을지.
- "적 대공 미사일"을 적 대함 미사일로 이해함. 기함의 헬기 · 드론을 쏘는 적 대공 미사일 얘기라면 따로 확인.

## 4. 문제 C — 블록 파괴가 없는 것처럼 느껴짐 (**확인 완료 · 수정 미착수**)

### 확인 결과
기능 자체는 있다: 내구 0 → 파괴 → 작동 멈춤(`ModuleInstance.TakeDamage`, `ModuleRuntime.Update`), 함교 파괴 페널티, 도해 빨간색, 효과음.

자동 검사 로그(`C:\NRmirror3\**\log_*.txt`) 피격 기록 4,981건 집계:

| 항목 | 수치 |
|---|---|
| 적 미사일이 함교에 맞은 비율 | **95%** (1,686발 중 1,608발) |
| 적 포탄 · 기총이 함교에 맞은 비율 | 52% (3,219발 중 1,677발) |
| 이미 부서진 칸에 또 맞은 피격 | **1,567건(31%)** — 이 피해는 전부 선체로 |
| 함교 말고 파괴된 블록 | **7번** (CIWS 3 · 레이더 3 · VLS 1) |

(자동 검사 전투 기록이라 실제 플레이와 완전히 같지는 않지만, 경향은 분명하다.)

### 원인
1. 피해가 함교 한 곳에 몰린다. 함교 내구 120, 다른 블록 25~45.
2. 함교가 부서진 뒤에는 부서진 칸 = 선체 100% 규칙 때문에 그 칸이 선체 피해만 받는 칸이 된다 → 다른 블록은 맞을 일이 없다.
3. 부서져도 배 모델이 그대로다. View 쪽에 파괴 반응이 없고, 레이더 안테나를 숨기는 정도만 있다.
4. 복구: 전투 중 부활 없음(응급 수리도 안 부서진 블록만). 정비 화면 안내는 "정비에서 수리된다"인데, 코드상으로는 집었다가 다시 놓아 새로 설치해야만 살아나는 것으로 보인다 — **실제 확인 필요**.

### 수정 계획 (기획 B와 합침)
1. **측정 검사부터**: 고정 기함에 미사일 · 드론 · 포격을 사방에서 → 칸별 피격 수 · 파괴 수 · 부서진 칸 피격 비율. 이후 모든 단계의 기준선.
2. **맞는 위치 분산**: 기획 B + 적 포격의 탄착 퍼짐.
3. **부서진 칸 규칙**: 피해 일부를 가장 가까운 살아 있는 블록으로 넘긴다(시작값 선체 50% · 옆 블록 50%).
4. **파괴 시각화**: 원래 재질 유지 + 그을림 덧그림, 연기 · 불씨 지속, 포신 처짐 · 안테나 꺾임, 파괴 순간 작은 폭발, 수리하면 복원.
5. **복구 경로**: 정비 화면에서 자동 수리로 정리(현재 동작 확인 후). 전투 중에는 손상 통제반이 시간을 들여 기능 50%로 임시 복구 → 기획 A로 이어짐.

### 밸런스 주의
분산하면 무기 블록(내구 25~45)이 훨씬 자주 부서지고, 함교 파괴와 선체 피해 일부는 줄어든다.
2 · 3단계 뒤 측정 검사로 비교해서, 블록 내구 또는 모듈이 받는 피해 비율(`BalanceConfig.moduleDamageShare` = 0.6)을 조정할지 정한다.
